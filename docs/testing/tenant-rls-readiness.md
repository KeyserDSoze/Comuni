# TDD — Readiness con prova RLS firmata, PostgreSQL reale (#126)

Il nuovo test `tests/backend/Comuni.Api.Tests/TenantRlsReadinessApiTests.cs` usa PostgreSQL della CI, lo SQL principal `comuni_app_runtime` per l'API e il login schema owner **solo** per creare/revocare/ripulire una chiave `ready*` fittizia e versionata. Non inserisce Comuni, membership o record. La prova HMAC usa lo stesso signer della revisione e `SET LOCAL` parametrizzato con rollback.

Casi richiesti: key ID e secret corretti => `/health/ready` 200; stesso ID ma secret errata => 503; revoca della key owner-only durante la vita della revisione => immediato 503; DB non raggiungibile => 503; in tutte le situazioni `/health/live` 200. Verificare `Cache-Control: no-store`, nessun secret nella risposta e contesto `comuni.tenant_assertion` NULL su una connessione runtime indipendente dopo il probe. Il codice controlla anche che PostgreSQL rifiuti una firma HMAC alterata.
