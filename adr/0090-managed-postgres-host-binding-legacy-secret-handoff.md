# ADR 0090 — Binding host PostgreSQL managed anche nel piano di handoff della secret legacy

- Data: 2026-11-18.
- Stato: **Accepted per guardia offline su piano Terraform sintetico**, non verifica TLS live.
- Issue: #107, sotto #49/#6, emenda ADR 0048 e ADR 0089; applica il confine di ADR 0044 e del gate staged-rollout.
- Riferimenti: [Terraform JSON plan](https://developer.hashicorp.com/terraform/internals/json-format), [Azure PostgreSQL TLS](https://learn.microsoft.com/en-us/azure/postgresql/security/security-tls-how-to-connect), [Npgsql SSL](https://www.npgsql.org/doc/security.html).

## Rischio e decisione

Il comando read-only `scripts/azure/check-legacy-postgres-handoff-plan.py` verificava il riferimento al secret versionato della candidata, ACA `Multiple`, stable al 100% e candidata allo 0% (#106), senza però confrontare `RuntimePostgres__ExpectedHost` con il **vero** Azure PostgreSQL Flexible Server. Un hostname di un altro server Azure potrebbe avere un certificato TLS valido e tuttavia essere un peer non autorizzato, oppure un host mancante farebbe fallire la candidata dopo l'handoff. Anche un piano `azurerm_container_app.main ["no-op"]` non garantisce quindi la correttezza **dello stato precedente**.

1. **Fonte indipendente:** leggere esclusivamente `planned_values.root_module.resources` nel medesimo `terraform show -json`, cercare **un'unica** risorsa `address=azurerm_postgresql_flexible_server.main` e `type=azurerm_postgresql_flexible_server`. Richiedere `values.name` e `values.fqdn` coerenti con il suffisso esatto `.postgres.database.azure.com` e il formato hostname consentito. Rifiutare duplicati, assenza, tipo diverso, IP/alias, FQDN non corrispondente a `name`, namespace fasullo, caratteri non ammessi e campi mancanti. Non prendere l'host da CLI, TF_VAR, Key Vault secret o env candidato.
2. **Binding applicativo:** nell'unico `template.container.env` già controllato da `validate_app`, esigere un'unica variabile `RuntimePostgres__ExpectedHost` con `value` identico all'FQDN managed e senza `secret_name`. Devono restare invariati `ConnectionStrings__Default` con `pg-<16hex>` e URI Key Vault `postgres-runtime-connection/<32hex>`, l'assenza di credenziali inline, nonché il vecchio `postgres-connection` app-scoped. La policy runtime `RuntimePostgresConnectionSettings` (ADR 0044) continua a richiedere `SslMode.VerifyFull` e il ruolo `comuni_app_runtime`; questa validazione del piano non apre socket né legge password o certificati.
3. **Invarianti mantenuti:** l'unica mutazione ammessa resta `["forget"]` del resource legacy **senza cancellazione Azure**, mentre la Container App e tutte le altre risorse devono essere `["no-op"]` con `before==after`. Continuano a essere obbligatori `Multiple`, stable 100%, candidata latest 0% e label approvata. Nessun `terraform apply`, nuovo secret in State, ALTER SQL, API .NET, modifica al frontend o cambi al workflow reale.
4. **TDD:** RED in `tests/infra/test_legacy_postgres_handoff_plan.py`, commit `6c8b04e7`, con fixture dotata di `planned_values` managed, hostname candidato corretto e casi negativi di mancanza/duplicazione/falsificazione delle risorse o dei valori e di env candidata falsificata (anche `before==after`). RED Terraform/Python verificabile nella CI del commit. GREEN `c1432b87`: funzionalità minimale su parser e `validate_app`, preservando tutti gli altri test. Chiusura #107 soltanto con **7/7 GitHub Actions verdi sullo stesso SHA HEAD finale** dopo ADR/docs.
5. **Sicurezza output:** il piano Terraform può contenere password, URI e dati di infrastruttura; messaggio di errore costante e non echo di input, dettagli eccezioni, host o valori. Usare runner privato, no plan su stdout/issue/tracing. Il test sul piano non è garanzia di corrispondenza con lo State/traffic live.

## Limiti e prerequisiti

Questo gate prova **solo coerenza sintattica di metadata pianificati**. Non valida un handshake TLS reale, catena root CA, esistenza del secret pinato, valore della stringa, credenziali SQL, autenticazione del server in VNet, clock/revocation, revisioni inactive, readiness, promotion/rollback o approvazioni indipendenti. Per il go-live servono review live degli owner e Security/Privacy, prove con due Comuni sintetici, CA e SAN, rete privata, gestione dei precedenti State snapshot e rotazione coordinata Key Vault/ACA. **#49/#6/#19** restano aperte. Non è stato eseguito alcun accesso Azure né sono stati utilizzati segreti o Comuni reali.

## Emendamento #108 / ADR 0091 — non fidarsi di snapshot Terraform discordanti

L'FQDN managed `planned_values` di ADR 0090 ora deve concordare anche con `resource_changes["azurerm_postgresql_flexible_server.main"]` `no-op` su `name/fqdn`. Una corrispondenza della sola env `RuntimePostgres__ExpectedHost` con il blocco `planned_values` non è più sufficiente; il gate controlla anche la coerenza dei campi security-relevant dell'ACA tra gli stessi due blocchi. Test Python RED→GREEN e motivazione in ADR 0091; la verifica resta offline, non un handshake TLS reale.
