# ADR 0082 — Sospensione e riattivazione Comune: COPY privato e logging SQL

- Data: 2026-11-18.
- Stato: Accepted **soltanto per test sintetici offline**; non autorizza operazioni per Comuni o persone reali.
- Issue: #98 (sotto-task P0 di #86), preserva ADR 0027 e ADR 0072; canale conforme alle ADR 0073 e 0078–0081.
- Specifiche: https://www.postgresql.org/docs/17/app-psql.html; https://www.postgresql.org/docs/17/sql-copy.html; https://www.postgresql.org/docs/17/runtime-config-logging.html.

## Problema

La procedura owner-only `scripts/postgres/set-organization-suspension.sql` riceveva UUID Comune, action, change ticket, approver e reason dall'environment client e li interpolava in `set_config(..., :'lifecycle_*', true)`. Il quoting di psql limita l'iniezione SQL, **non la registrazione dei valori** da `log_statement=all`, `log_min_error_statement` e strumenti di audit che acquisiscono il SQL text. Lo script attua il contenimento del Comune potenzialmente compromesso e deve preservare logging e audit amministrativo senza inviare i riferimenti personali del change come literal SQL.

## Decisione

1. Modificare **solo il trasporto degli input** di `set-organization-suspension.sql`, preservando il `DO $lifecycle$` senza alcun bypass. La policy owner di `platform.organizations` e `platform.audit_events`, UUID non zero, organization già attivata, `suspend`/`reactivate`, ticket/reviewer/reason formattati, `SELECT ... FOR UPDATE`, idempotenza sulla destinazione, audit append-only `platform.organization.suspended`/`platform.organization.reactivated` nello stesso commit, immutabilità di membership e feature flags, denied runtime e isolamento tenant rimangono invariati. Nessun nuovo endpoint API, permesso, migration, UI o schema persistente.
2. `psql \getenv` resta un *preflight locale* per cinque valori: `COMUNI_LIFECYCLE_ORGANIZATION_ID`, `COMUNI_LIFECYCLE_ACTION`, `COMUNI_LIFECYCLE_CHANGE_TICKET`, `COMUNI_LIFECYCLE_APPROVER`, `COMUNI_LIFECYCLE_REASON_CODE`. L'helper esistente `stream-private-input.py organization-lifecycle` legge esclusivamente quei cinque campi tramite allowlist, rifiuta missing/empty, >1024 byte per campo e envelope >8192 byte, con errore costante senza stdout o traceback. Non accetta dati collaterali o input in argv.
3. Nella transazione creare `CREATE TEMP TABLE pg_temp.comuni_private_input(payload text NOT NULL) ON COMMIT DROP` e usare comando statico `\copy pg_temp.comuni_private_input(payload) FROM PROGRAM 'python3 scripts/postgres/stream-private-input.py organization-lifecycle' WITH (FORMAT csv)`. Il programma gira **localmente al client**: una riga base64(JSON) è trasferita con protocollo COPY STDIN. `WITH private_json AS (... convert_from(decode(payload, 'base64'), 'UTF8')::jsonb ...)` decodifica dentro PostgreSQL e fornisce i cinque `secret ->> 'COMUNI_LIFECYCLE_*'` alla SELECT statica che usa `set_config(..., true)` transaction-local, poi `\\gset` senza stampa. Nessun `:'lifecycle_*'` nel testo SQL. La TEMP scompare a commit o rollback.
4. Il percorso richiede `psql -X -q -v ON_ERROR_STOP=1` e **working directory nella root di un checkout verificato/trusted**, un runner privato con DB schema-owner, rete PostgreSQL riservata e TLS VerifyFull. Vietati `-a/-e`, `set -x`, invocazione manuale dell'helper, dump di environment/stdout, passaggio di change references in issue o command line. `OrganizationLifecycleTests` aggiorna cwd dalla posizione dello script; `EmergencyAdminStagingTests`, `PostEmergencyAdminEnrollmentTests` e `OrganizationActivationTests` già usano cwd trusted e devono continuare a farlo.
5. **TDD su main**: RED Python stdlib per temp COPY, command costante, cinque chiavi esatte, un record e input missing/empty/oversize senza echo; RED xUnit/PostgreSQL 17 `psql` con subject-free canary sinteticamente unici *ticket e approver*, entrambe le transizioni `suspend` e `reactivate`, `PGOPTIONS=-c log_statement=all -c log_parameter_max_length=-1 -c log_parameter_max_length_on_error=-1`. Leggere i veri `docker logs` in memoria, richiedere `statement: COPY`, verificare che i canary non appaiano nel testo del server log; **non stampare log grezzi in failure**. In CI container o log non disponibili causano failure. Regressioni di accesso API 403, cross-tenant, audit, concurrency, no-op, pending/unknown, runtime denial e emergency #85/#87 restano obbligatorie. Completamento soltanto dopo CI finale **7/7 jobs verdi sullo stesso SHA HEAD di main** (backend PostgreSQL, Playwright, Terraform, CodeQL C#/JS, dipendenze e Docker).

## Confini e limiti

**Base64 non cifra e non anonimizza.** Il payload COPY e la temp table rimangono reversibili e possono essere catturati da processi, proxy, error context, logger del protocollo, pgAudit, dump, SIEM o APM: il test PostgreSQL 17 prova la riduzione di leakage **delle statement SQL configurate in CI**, non una garanzia universale di privacy o il comportamento Azure live. La sospensione blocca nuove richieste API protette; non revoca di per sé token e sessioni IdP o interrompe transazioni già in corso. La stringa reviewer e il ticket non costituiscono firma, MFA o quattro occhi autentici (#84). La #86 resta APERTA per activation/registration owner-only, inventario completo, log Azure/pgAudit/SIEM, retention, sicurezza operativa e review GDPR; #92/#49 restano gate ambientali. **Niente uso con Comuni, credenziali o identità reali fino alle approvazioni Security/Privacy/Legal.**
