# ADR 0080 — Revoca Admin OIDC: canale COPY privato, senza literal SQL

- Data: 2026-11-18.
- Stato: Accepted soltanto per test sintetici offline; vietato l'uso con identità reali prima di security/privacy review.
- Issue: #96 (sotto-issue P0 della #86), mantiene ADR 0070 e riusa il canale ADR 0073/0078/0079.
- Specifiche: https://www.postgresql.org/docs/17/app-psql.html, https://www.postgresql.org/docs/17/sql-copy.html, https://www.postgresql.org/docs/17/runtime-config-logging.html.

## Minaccia

La procedura owner-only revoke-admin.sql interpolava issuer, subject, ticket e altri input con la forma psql quoted literal (due punti e apostrofi) in una chiamata set_config. PostgreSQL con log_statement=all o altri audit del testo SQL può catturare questi valori; psql -q impedisce l'echo lato client ma non la registrazione sul server. Non è accettabile attenuare il logging amministrativo solo per nascondere PII.

## Decisione

1. Modificare solo il trasporto dei sei campi dell'operazione revoke-admin, senza cambiare il DO server-side di autorizzazione. I campi obbligatori restano COMUNI_REVOKE_ADMIN_ORGANIZATION_ID, COMUNI_REVOKE_ADMIN_IDENTITY_ISSUER, COMUNI_REVOKE_ADMIN_SUBJECT, COMUNI_REVOKE_ADMIN_CHANGE_TICKET, COMUNI_REVOKE_ADMIN_APPROVER, COMUNI_REVOKE_ADMIN_REASON_CODE. Il client psql verifica soltanto la presenza delle variabili con \getenv; non le interpola nel testo SQL inviato a PostgreSQL.
2. All'interno della transazione usare la TEMP TABLE pg_temp.comuni_private_input(payload text NOT NULL) ON COMMIT DROP. Il comando statico \copy ... FROM PROGRAM 'python3 scripts/postgres/stream-private-input.py revoke-admin' WITH (FORMAT csv) emette dal client un solo record base64(JSON) che viaggia nel protocollo COPY FROM STDIN. La query server-side fissa decodifica con convert_from(decode(payload, 'base64'), 'UTF8')::jsonb, seleziona le sei chiavi e le passa a set_config(..., true) transaction-local, con \gset senza output. Nessun input sensibile entra nel testo della query.
3. Il programma helper è una allowlist esplicita: accetta soltanto le sei chiavi esatte in modalità revoke-admin; rifiuta missing, empty, valori oltre 1024 byte o envelope oltre 8192 byte; in errore nessun stdout, stderr costante e nessun traceback. Il programma non inoltra variabili estranee, non mette input in argv e non viene invocato manualmente in terminale.
4. **Invarianti di sicurezza immutate:** caller owner delle tabelle organization/memberships/audit; organization esistente, attivata e non sospesa; verifica issuer HTTPS e subject esatti, ticket e reviewer; lock SELECT FOR UPDATE sull'organization; divieto di revocare l'ultimo Admin attivo e issuer-bound; disabilitazione solo della membership selezionata; audit append-only nello stesso commit; retry idempotente soltanto con lo stesso ticket e hash, rifiuti per ticket riusato, runtime SQL, tenant estranei, concurrent revocations. Non aggiungere API, token, ruoli, grant, RLS bypass o migration.
5. **TDD:** test Python RED controlla comando statico, assenza di literal inline, allowlist stretta, round-trip di input SQL-like e rigetto senza echo. Test xUnit RED/Green con psql e PostgreSQL 17 impone log_statement=all, log_parameter_max_length=-1 e log_parameter_max_length_on_error=-1; con issuer e subject canary indipendenti ispeziona i veri docker logs senza stamparli e richiede una statement COPY e nessun canary. In CI l'accesso ai log è obbligatorio. Regressioni xUnit su ultimo Admin, concorrenza, retry, OIDC RS256, cross-tenant, runtime e audit; Playwright, Terraform, CodeQL, SCA e Docker restano gate obbligatori: chiudere solo con 7/7 job verdi sul medesimo SHA main.
6. Il processo psql deve partire dalla root di un checkout fidato, con -X -q -v ON_ERROR_STOP=1, su rete privata e TLS VerifyFull; non usare -a/-e, set -x, piping dello stdout dell'helper o trasporto di issuer/sub tramite GitHub issue. AdminRevocationTests usa WorkingDirectory=Root(); AdminRecoveryTests era già impostato.

## Limiti di garanzia

**Base64 non cifra né rende anonimo l'input.** Il payload del COPY resta leggibile dal destinatario, client/processi e da eventuali proxy, log di payload/pgAudit, error context, SIEM, dump e trace. I test nel container PostgreSQL 17 verificano la mancata apparizione dei canary nel *testo delle statement* del solo ambiente di prova: non garantiscono redazione universale sui sistemi Azure o sulle pipeline SIEM. Il change ticket non autentica le persone; MFA, identity proof, approvazione indipendente e coordinamento revoca sessioni IdP restano #84. La #86 resta aperta per lifecycle, platform operator, onboarding/registration, retention, logging reale e privacy review; #92 per pgAudit/Azure, #49 per TLS/secret rollout. Nessuna autorizzazione all'uso in produzione.
