# ADR 0109 — Prova reale pgAudit su logging collector file PostgreSQL 17

- Data: 2026-11-20.
- Stato: **Accepted solo per la fixture sintetica e disposable PostgreSQL 17/pgAudit**, non certificazione Azure/produzione.
- Issue: [#125](https://github.com/KeyserDSoze/Comuni/issues/125), figlia di #92/#86 e correlata a #89/#5/#19. ADR precedenti 0076, 0098, 0107, 0108.
- Fonti: [PostgreSQL 17 — Error Reporting and Logging](https://www.postgresql.org/docs/17/runtime-config-logging.html), [PostgreSQL 17 — Log File Maintenance](https://www.postgresql.org/docs/17/logfile-maintenance.html), [pgAudit — README](https://github.com/pgaudit/pgaudit/blob/main/README.md).

## Rischio e premessa

I test precedenti acquisiscono `docker logs` e cercano password/verifier SCRAM, componenti salt/StoredKey/ServerKey e envelope `base64(JSON)` di `\\copy` (ADR 0107/0108). Questo prova il solo canale stderr del processo PostgreSQL con il logging collector disattivato. PostgreSQL 17 supporta `logging_collector=on`: i messaggi standard/pgAudit possono essere scritti nei file indicati da `pg_current_logfile()`, anziché nella console del container. Un log sink indipendente è una diversa superficie di accesso, retention e potenziale fuga, non una prova equivalente a Docker logs. pgAudit scrive attraverso il logging facility PostgreSQL, non direttamente nel sistema di audit esterno.

## Decisione TDD

1. Conservare tutte le verifiche già presenti nel PostgreSQL17/pgAudit usa-e-getta con `shared_preload_libraries=pgaudit` e native `log_statement=all`, `log_parameter_max_length=-1`, `log_parameter_max_length_on_error=-1`. Dopo aver esercitato i 12 percorsi owner-only e i due SCRAM, riavviare **solo il container disposable** dopo `ALTER SYSTEM SET logging_collector='on'`, `log_destination='stderr'` e `log_filename='audit-ci.log'`. Nulla di ciò tocca Azure né database di produzione.
2. Attendere la disponibilità TCP/psql del riavvio e verificare sia `current_setting('logging_collector')`/`log_destination` sia il nome del file con `pg_current_logfile()`. **Non** inventare né leggere altri file nel percorso dati: accettare solo il file statico previsto `log/audit-ci.log`, corrispondente al path fisso letto con `docker exec ... cat`. Tenere il contenuto in memoria e rifiutare file assente, vuoto o dal confine iniziale non coerente. La fixture viene comunque eliminata in `finally`.
3. Eseguire i **veri** `provision-runtime-role.sql` e `provision-platform-read-role.sql` con nuove password fittizie, verificando rotazione SCRAM da `pg_authid`, login dei due principal, redazione `ALTER ROLE` per ogni ruolo e `ROLE,GRANT`. In questa sessione la prova SCRAM continua a usare `pgaudit.log_parameter=on`, con `role,ddl,write,function` attivi; nessuna nuova assegnazione di privilegi a runtime.
4. Eseguire il vero `stage-tenant-proof-key.sql` con ID e signing key fittizi, sulla medesima istanza dopo riavvio. L'owner-only script preserva il preflight `pgaudit.log_parameter=off` **soltanto per i valori sensibili**, continuando a generare `FUNCTION,DO`, `WRITE,INSERT` e `statement: COPY`. Un read-back SQL statico controlla lo staging senza incorporare il key ID/secret nella query.
5. Il nuovo `assert_file_collector_privacy` esamina **esclusivamente il log dopo riavvio** e l'output privato stdout/stderr dei nuovi script, riutilizzando l'analizzatore SCRAM completo con l'opzione `required_commands=('ALTER ROLE',)` (i CREATE erano già verificati prima di riavviare). Aggiunge il controllo dell'envelope esatto `base64(JSON)` e della chiave sintetica raw/base64, e richiede metadati owner `FUNCTION/WRITE/COPY`. Non stampare mai password, verifier, chiavi, log raw, frammenti, URL di secret o stdout psql.
6. Test-first RED [`e396e37`](https://github.com/KeyserDSoze/Comuni/commit/e396e37793cc6028c42aaf3196441152dbf20e96), [run 44771491898](https://github.com/KeyserDSoze/Comuni/actions/runs/44771491898), Terraform/Python fallito con **6 failure e 24 error** per assenza del nuovo analizzatore e della prova reale. Prima implementazione [`62ad77e`](https://github.com/KeyserDSoze/Comuni/commit/62ad77eb09d2e2a8903349bfe28e4e8cd8eb82ad), contratto statico [`a75970b`](https://github.com/KeyserDSoze/Comuni/commit/a75970b2e021336951661555e26a341400b006a5). ## Limiti obbligatori

La prova misura il file di log del **logging collector upstream PostgreSQL17 con la versione pgAudit installata nella fixture Debian**; **non equivale a** `pgAuditLogToFile` di Azure PostgreSQL Flexible Server, logging e streaming Azure Monitor, Log Analytics, SIEM/APM/proxy, log rotation, fileset di backup, storage/retention, letture DBA, Key Vault o compliance GDPR. Non dimostra accesso reale alle credenziali, MFA/change approval, replica multi-node o rotazione zero-downtime. Se una forma sensibile compare nel file, il gate deve fallire; non ridurre audit o `log_statement` per nasconderla. #92/#86/#89/#19/#5 restano aperte fino a verifiche autorizzate reali.
