# ADR 0047 — Preflight metadata-only di tutte le revisioni prima di ritirare la secret SQL legacy

- Stato: Accepted per **inventario read-only e validazioni offline**, NON per rimozione reale di segreti né migrazione dello State.
- Data: 2026-11-16.
- Issue: #54, sotto #49/#5/#6; ADR collegati: 0043–0046.
- Fonti ufficiali: [Azure Container Apps — Manage secrets](https://learn.microsoft.com/en-us/azure/container-apps/manage-secrets), [Azure CLI — `containerapp revision list --all`](https://learn.microsoft.com/en-us/cli/azure/containerapp/revision), [Azure Container Apps — Revisions](https://learn.microsoft.com/en-us/azure/container-apps/revisions), [HashiCorp — Remove a resource from state](https://developer.hashicorp.com/terraform/language/state/remove).

## Minaccia e dipendenze

L'applicazione utilizza un solo runtime SQL `comuni_app_runtime` e un database PostgreSQL multi-organization, oggi protetti da RLS firmata. La vecchia secret ACA `postgres-connection` è app-scoped, punta al vecchio Key Vault secret **versionless** e il suo valore Terraform contiene una password SQL con `SSL Mode=Require` nello State e potenzialmente negli snapshot storici. #50–#52 hanno introdotto una nuova connessione candidato `pg-<16hex>` con HMAC e host/TLS approvati, ma **non** hanno migrato le revisioni stabili/inattive. #53 ha volutamente proibito lo state handoff nel normale stage ACA a 0% senza una procedura owner separata.

Microsoft precisa che, prima di **eliminare una secret Container Apps**, bisogna distribuire una revisione che non la referenzi e disattivare tutte quelle che la utilizzano; `revision list --all` include anche le inattive. I secrets sono app-scoped, e una revisione inattiva può essere riattivata. Le operazioni di `listSecrets` possono esporre valori: non sono adatte a un controllo automatizzato con privilegi di sola lettura metadati.

## Decisione

1. **Preflight standalone read-only.** `scripts/azure/preflight-legacy-postgres-retirement.py --app <prefix>-app --resource-group <prefix>-rg` richiede `az containerapp revision list --all` e per ogni nome restituito un `az containerapp revision show` con output JSON, senza shell, senza comandi mutativi e senza richiedere permessi `listSecrets`. Controlla che non esistano revisioni omesse/duplicate, che esista almeno una revisione attiva, che template/containers/env siano completi e coerenti con l'unica API/PWA, che `ConnectionStrings__Default` appaia una sola volta e referenzi un secret `pg-<16hex>` senza password inline, e che **nessun** env di alcuna revisione referenzi la vecchia `postgres-connection`, anche sotto altro nome o se inattiva.
2. **Fail closed e non-disclosure.** Qualunque risposta CLI incompleta, mancanti permessi Azure, JSON invalido, schema ignoto, revision count non verificabile (limite locale 200) o altra identità app/resource group produce errore statico privo di nomi/URI/valori. I risultati di successo non sono una autorizzazione a eliminare la secret; sono un inventario nel momento della lettura, soggetto a race con una nuova attivazione o modifica. Un controllo ripetuto e procedure owner con lock/change window restano obbligatori.
3. **Operazioni distinte:** (A) **Inventario** delle revisioni (questa slice, anche inattive); (B) **Trasferimento di gestione Terraform** del vecchio `azurerm_key_vault_secret.postgres_connection` tramite `removed { lifecycle { destroy = false } }` insieme alla sostituzione sicura dei riferimenti con un URI di secret esterno e all'approvazione del piano; (C) **Eliminazione separata** di secret ACA/Key Vault legacy, rotazione/invalidazione credenziale SQL e valutazione backup/state storici. (B) non equivale a (C): `destroy=false` impedisce la distruzione Azure al momento della rimozione dallo State, ma **non** sanifica snapshot preesistenti. Una revisione inattiva con legacy ref blocca il preflight più strettamente delle linee guida di disattivazione Microsoft, così da ridurre rischi di ripristino accidentale. Il workflow `deploy.yml` e `infra/main.tf` non sono modificati: nessun `terraform apply`/state operation live.
4. **TDD.** RED nuovi test fake-Azure-CLI per active/inactive, consumer inattesi, valori inline, duplicati, dati incompleti e leak; GREEN strumento puro metadata-only. Chiusura #54 subordinata a suite infra Python/Terraform e all'intera CI 7/7 della stessa SHA `main`. Senza un accesso Azure reale resta da documentare un esito operativo, non si dichiara alcun segreto rimosso.

## Non obiettivi / rischi residui

Non si fa discovery dei componenti Dapr, di altre applicazioni/slot o di consumatori PostgreSQL esterni, non si leggono segreti né snapshot dello State; non si verificano permessi reali, OIDC, VNet, root CA, il protocollo RLS su due Comuni né la capacità di rollback. Non si disattivano revisioni e non si applicano modifiche di Terraform. L'epica #49 resta aperta fino a prove reali e autorizzazione alla migrazione e rotazione, con backup e tutela delle copie storiche. Non si considera automaticamente una successiva cancellazione sicura soltanto perché il preflight è verde.
