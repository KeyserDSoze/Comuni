# ADR 0087 — Trasporto privato dei metadati di ritiro delle chiavi RLS

- Data: 2026-11-18.
- Stato: **Accepted per test sintetici PostgreSQL 17**, NON per rollout o revoca di chiavi reali.
- Issue: #103, sotto-incremento di #86/#19; aggiorna il solo trasporto del ritiro descritto da ADR 0040/#46; segue ADR 0073/0074.
- Fonti: [psql PostgreSQL 17](https://www.postgresql.org/docs/17/app-psql.html), [COPY](https://www.postgresql.org/docs/17/sql-copy.html), [logging](https://www.postgresql.org/docs/17/runtime-config-logging.html), [locks](https://www.postgresql.org/docs/17/explicit-locking.html).

## Minaccia e perimetro

L'owner-only `retire-tenant-proof-key.sql` non riceve una chiave HMAC, ma trasmetteva `TENANT_PROOF_RETIRE_KEY_ID`, `TENANT_PROOF_REPLACEMENT_KEY_ID` e `TENANT_PROOF_GRACE_SECONDS` con `psql :'retire_id' / :'replacement_id' / :'grace_secs'` direttamente nel testo SQL. Il quoting protegge da injection ma `log_statement=all`, error statement logging e SQL audit possono conservare ID e metadati della revoca. Non disabilitare logging per aggirare il rischio.

## Decisione

1. Gli esatti tre input restano in ambiente **privato** del runner. `psql \\getenv` controlla presenza e il programma statico locale `python3 scripts/postgres/stream-private-input.py retire-tenant-proof` inoltra **solo** questi nomi, rifiutando missing/empty/oversize (>1024 byte/campo) con stderr costante e senza payload, altre env, argomenti dinamici o traceback. Nessun segreto HMAC viene letto da questa procedura. Il payload è una riga **base64(JSON) reversibile** con limite 8192 byte: non cifra né anonimizza.
2. La transazione `BEGIN` ora precede la validazione del contenuto per consentire `CREATE TEMP TABLE pg_temp.comuni_private_input(payload text NOT NULL) ON COMMIT DROP`. Il comando client-side statico `\\copy pg_temp.comuni_private_input(payload) FROM PROGRAM 'python3 scripts/postgres/stream-private-input.py retire-tenant-proof' WITH (FORMAT csv)` usa COPY FROM STDIN del server; query statica legge JSON da `convert_from(decode(payload,'base64'),'UTF8')::jsonb` ed esegue `set_config(...,true)` per le tre GUC transaction-local. `\\gset` evita output del result set. Il validatore usa solo `current_setting(...,true)`, non interpolazioni `:'...'`.
3. **Nessuna modifica di invarianti della rotazione:** ID ASCII `^[a-z][a-z0-9_-]{0,31}$`, ID distinti, grace 0..3600, `SET LOCAL lock_timeout='10s'`, `LOCK TABLE ... IN SHARE ROW EXCLUSIVE MODE`, successore esistente/non revocato/not_before valido/valid_until oltre **grace+300s**. `UPDATE` accorcia `valid_until` con `least()` e mette `revoked_at` soltanto quando grace=0, senza cancellare revoche precedenti. Retry non estende nulla; tentativi reciproci concorrenti serializzano; ruolo runtime non ottiene privilegi aggiuntivi. Il fallimento validazione dentro `BEGIN` provoca errore `ON_ERROR_STOP` e **rollback automatico** della connessione `psql`, comprese TEMP e GUC.
4. **TDD su main**: RED Python stdlib su allowlist esatta, una riga base64(JSON), input assenti/vuoti/oversize, env non inoltrata, COPY statico, assenza literal, persistenza guardia lock/300s/least. RED xUnit/PostgreSQL 17 con canary sintetici target/successor, `PGOPTIONS` per `log_statement=all` e massimo logging parametri, lettura di veri `docker logs` server (indisponibilità su CI = errore), presenza `statement: COPY` e assenza canary, senza stampare log grezzi. Regressioni `TenantProofRetirementGuardTests` devono mantenere invalid/missing/short/future/revoked successor, RLS tenant, runtime deny, retry monotono e concorrenza. Chiusura #103 solo con **7/7 CI** sul medesimo SHA finale `main` (.NET/Postgres, Playwright, Terraform/Python, NuGet/npm audit, CodeQL C#/JS e Docker).
5. Esecuzione soltanto con prove sintetiche in runner privato, schema-owner, root checkout trusted e TLS VerifyFull, con `psql -X -q -v ON_ERROR_STOP=1 -f scripts/postgres/retire-tenant-proof-key.sql`; vietati `psql -a/-e`, `set -x`, env dump, helper invocato manualmente o qualsiasi parametro contenente ID reale in CLI/log. Una revoca resta un change **indipendente**, dopo verifica di staging Key Vault, repliche ACA e rollback in ambiente autorizzato.

## Limiti

La busta base64(JSON) è osservabile nel protocollo COPY/TEMP, possibili error context, proxy, pgAudit/Azure/SIEM, backup e retention: i test degli **statement** non dimostrano riservatezza end-to-end. ID e grace non sono password, ma i metadati di revoca restano sensibili nel threat model operativo. Non esistono prove live su Azure, Key Vault, managed PostgreSQL, pgAudit, IdP/MFA, clock skew o aggiornamento delle repliche. #86, #19, #49, #92, #5 e #6 rimangono aperte; la review Security/Privacy e la validazione di approval/mandato sono prerequisiti non soddisfatti. Nessuna rotazione produttiva autorizzata.
