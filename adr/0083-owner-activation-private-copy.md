# ADR 0083 — Attivazione Comune created → active: input owner-only tramite COPY privato

- Data: 2026-11-18.
- Stato: **Accepted soltanto per test sintetici offline**; non abilita activation reale o onboarding senza change approval e verifiche IdP/Privacy.
- Issue: #99, incremento isolato P0 della #86; preserva i confini di ADR 0038 e impiega il canale documentato in ADR 0073/0078–0082.
- Specifiche PostgreSQL 17: https://www.postgresql.org/docs/17/app-psql.html; https://www.postgresql.org/docs/17/sql-copy.html; https://www.postgresql.org/docs/17/runtime-config-logging.html.

## Minaccia

Il precedente `scripts/postgres/activate-organization.sql` trasferiva UUID del Comune, change ticket e reviewer con `set_config(..., :'activate_*', true)`. Il quoting limita SQL injection, ma comunica i riferimenti approvativi come **literal della query SQL**, visibili al PostgreSQL 17 con `log_statement=all`, audit del SQL text e possibili error statement log. `psql -q` disabilita l'echo client, **non** rimuove i dati dal testo SQL ricevuto dal server. Non disabilitare logging del server per mascherare il problema.

## Decisione ristretta a #99

1. Sostituire **soltanto il trasporto di tre valori** nell'esistente `activate-organization.sql`, preservando in modo integrale il blocco `DO $activation$` e le sue condizioni: schema owner di `platform.organizations`, `platform.organization_memberships` e `platform.audit_events`; UUID non-zero valido, approvazioni formattate, ente esistente e non sospeso, `SELECT ... FOR UPDATE` sull'organizzazione; presenza del **primo Admin OIDC attivo con issuer HTTPS** e modulo protocol disabilitato, nessun modulo già abilitato; update solo di `is_activated` e audit append-only `platform.organization.activated` **atomici**, retry no-op e concurrent activation serializzate. Nessun grant, endpoint .NET, React, migration, modifica multi-organization o bypass RLS.
2. Le variabili obbligatorie restano `COMUNI_ACTIVATE_ORGANIZATION_ID`, `COMUNI_ACTIVATE_CHANGE_TICKET` e `COMUNI_ACTIVATE_APPROVER`. `psql \getenv` le controlla solo nel client. Il programma `python3 scripts/postgres/stream-private-input.py activate-organization` legge **esattamente** i tre campi allowlisted; input missing/empty, >1024 byte per campo o envelope >8192 byte sono rifiutati con **messaggio d'errore fisso** senza stdout, traceback o valori negli argv. Non inoltra l'intero environment.
3. Prima del `DO`, nella stessa transazione creare `CREATE TEMP TABLE pg_temp.comuni_private_input(payload text NOT NULL) ON COMMIT DROP` e usare `\copy pg_temp.comuni_private_input(payload) FROM PROGRAM 'python3 scripts/postgres/stream-private-input.py activate-organization' WITH (FORMAT csv)`. Il comando è **statico**, eseguito dal client `psql` nella root del checkout trusted, e manda una singola riga **base64(JSON)** tramite protocollo `COPY FROM STDIN`, non nel SQL literal. Una SELECT statica legge `convert_from(decode(payload, 'base64'), 'UTF8')::jsonb` e `secret ->> 'COMUNI_ACTIVATE_*'` per `set_config(..., true)` transaction-local, con `\\gset` senza output. La TEMP scompare al commit/rollback.
4. Uso ammesso solo per test: `psql -X -q -v ON_ERROR_STOP=1 -f scripts/postgres/activate-organization.sql`, checkout trusted, runner privato, credenziale DB schema owner e rete TLS VerifyFull; non usare `psql -a/-e`, shell `set -x`, stampa dell'helper, export in issue o log di change references. La fixture `OrganizationActivationTests` parte già dalla root del repository e mantiene questa garanzia.
5. **TDD RED → GREEN su `main`:** Python stdlib verifica comando statico, tabella temp, no `:'activate_*'`, allowlist esatta e un record base64(JSON), rifiuti missing/empty/oversize senza echo. xUnit/PostgreSQL 17 crea un ente e primo Admin synthetic, esegue activation con ticket/reviewer canary indipendenti sotto `PGOPTIONS=-c log_statement=all -c log_parameter_max_length=-1 -c log_parameter_max_length_on_error=-1`, legge i **veri `docker logs`** del server in memoria senza stamparli, richiede `statement: COPY` e vieta entrambi i canary. In CI i log Docker non disponibili devono causare failure, non skip. Conservare regressioni existing su pending/active/suspended, Admin assente/legacy, module gates, idempotenza, concurrency, runtime SQL deny e isolamento tenant; React/Playwright, Terraform, CodeQL C#/JS, SCA e Docker restano gate. Chiudere #99 soltanto con **7/7 job verdi sullo stesso SHA finale di `main`**.

## Limiti e dipendenze

**Base64 non cifra né anonimizza:** il payload è recuperabile nel protocollo COPY, nella temp table, dai processi, da proxy, error context, trace, dump, pgAudit, APM e SIEM. Il controllo canary certifica esclusivamente che il **testo dello statement SQL** nel PostgreSQL 17 disposable non riporti ticket/reviewer; non garantisce assenza di PII da ogni fonte reale in Azure. La procedura non autentica reviewer, incarico comunale, IdP/MFA o legittimità del change. La #86 resta aperta per il separato `register-organization.sql`, altri script owner-only e review reale Azure/pgAudit/SIEM/retention/Privacy; #84 per recovery/approvazioni IdP e #49/#92 per connessioni/logging. **Nessun uso con Comuni o identità reali è autorizzato** da questi test.
